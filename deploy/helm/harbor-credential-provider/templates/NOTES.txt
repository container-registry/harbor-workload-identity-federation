{{- if and .Release.IsInstall $restart }}
IMPORTANT: this is a first install. The DaemonSet controller puts an installer
pod on every eligible node at once, and maxUnavailable bounds updates, not
creation, so nothing serializes the kubelet restarts this time round. Running
containers survive a kubelet restart, but the nodes do go NotReady together for
a few seconds. See "First Install" in the chart README for the two ways around
it: install with --set kubelet.restart=false and switch it on as a second
upgrade, or install onto labelled batches of nodes with --set nodeSelector.
{{ end }}

{{- if and (not .Values.kubelet.configure) (has .Values.profile (list "eks" "aws")) }}

Kubelet configuration is off, which is correct for this profile on nodes running
the EKS-optimized AL2023 AMI: its kubelet already starts with the credential
provider flags pointing at /etc/eks/image-credential-provider. Bottlerocket, a
custom or self-managed AMI, and nodes outside EKS do not set those flags.
Confirm they are present before testing pulls:

  --image-credential-provider-bin-dir=/etc/eks/image-credential-provider
  --image-credential-provider-config=/etc/eks/image-credential-provider/config.json

{{- else if not .Values.kubelet.configure }}

IMPORTANT: Kubelet configuration is disabled. You must configure the kubelet
on each node to use the installed credential provider paths for your profile:

  --image-credential-provider-bin-dir=<profile bin dir>
  --image-credential-provider-config=<profile config path>

{{- else if and (not $restart) (eq .Values.profile "k3d") }}

reads the drop-in only when it starts.

logs print the command with the cluster and node names filled in.

In Harbor 2.15.12 or newer, the Trusted Issuer for this cluster must have its
audience field set to {{ include "harbor-credential-provider.audience" . }}. Do not add iss or aud claim
rules; Harbor rejects them. A Trusted Issuer upgraded from an older Harbor may
have no audience and reject every token until it is set.
